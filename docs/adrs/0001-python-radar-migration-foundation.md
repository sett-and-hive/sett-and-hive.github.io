# ADR 0001: Python Radar Migration Foundation

## Status

Accepted

## Context

The repository currently publishes a static technology radar generated by an
external JavaScript toolchain. The committed output in `tech-radar/` can drift
from `tech-radar.json`, and the in-repo implementation is effectively bundled
and opaque.

The migration needs a first-party Python toolchain that favors:

- explicit validation
- deterministic generation
- testability
- strong engineering governance
- compatibility with the existing published `tech-radar/` path

## Decision

We will establish the migration on the following foundation:

- Python `3.14` is the target interpreter for the new toolchain.
- `uv` is the package and workflow manager.
- `ruff` is the primary Python linting and formatting tool.
- `pytest` with `100%` branch coverage is the baseline automated test standard.
- Contract tests complement unit tests for generated artifact compatibility.
- `MkDocs` with Material is used for engineering documentation.
- `docs/adrs/` records significant architectural decisions.
- `docs/designs/` records phase designs and parallelizable task breakdowns.
- `pre-commit` is the default enforcement point for local workflow automation.
- `pip-audit`, `gitleaks`, and `grype` form the baseline security scanning posture.
- `tech-radar/` remains the published path until a later ADR changes it.

## Consequences

### Positive

- The migration gets explicit delivery rules before implementation detail sprawl.
- Testability and reproducibility become part of the architecture, not cleanup work.
- Documentation is treated as part of the system, not an afterthought.

### Negative

- Tooling setup is stricter and heavier than the current repository.
- Python `3.14` may require explicit compatibility work across parts of the ecosystem.
- Mutation testing and strict TCR practice increase short-term development cost.

## Follow-On Decisions

- The exact Python package layout for radar generation.
- The rendering strategy for reproducing or intentionally evolving the current UX.
- The contract surface that defines backward compatibility for the published site.
